# Seedance2 P0 PWA Storyboard Field Consumption Matrix v0.2

Status: P0 field-consumption boundary.
Scope: Seedance2 prompt knowledge enrichment for the existing PWA storyboard table.

## Core Boundary

New knowledge must fit the current PWA storyboard result fields only:

```text
序号
人物
运镜
景别
画面描述
角色动作
对白/旁白
分镜提示词
时长(秒)
操作
```

Runtime code fields:

```text
shot_index
person
camera
shot_size
visual_description
character_action
dialogue_or_narration
prompt_text
duration_seconds
status / note
```

This work is a knowledge-quality upgrade. It must not add new PWA columns, new generation stages, new provider logic, new export shape, or a separate product.

## Existing Field Mapping

| UI field | Runtime field | Can KB enrich it? | Allowed knowledge | Must not do |
| --- | --- | --- | --- | --- |
| 序号 | `shot_index` | No | None. Keep row order generated by the existing storyboard flow. | Do not let KB change indexing rules. |
| 人物 | `person` | No creative enrichment | Only preserve accepted-body characters or explicit role labels. | Do not invent characters; do not put location, style, action, camera terms, or KB terms here. |
| 运镜 | `camera` | Yes | Film camera movement, anime camera movement, camera angle, lens feeling, motion direction, static shot. | Do not stack conflicting movements; do not hide shot size here; do not write only cinematic or decorative terms. |
| 景别 | `shot_size` | Yes | Wide, full, medium, medium close-up, close-up, extreme close-up, insert, detail, aerial/overhead scale when appropriate. | Do not merge with `camera`; do not pick a scale that contradicts visible action or micro-expression detail. |
| 画面描述 | `visual_description` | Yes | Scene space, subject placement, environment path, material, light, color, air medium, composition, depth, focus. | Do not invent unsupported props, weather, world facts, source image details, OCR, filenames, or tutorial wording. |
| 角色动作 | `character_action` | Yes | Visible action, facial cue, breath, gaze, posture, hand movement, step, spacing, reaction, blocking. | Do not output abstract emotion only; do not add close-up facial details in wide shots; do not invent psychology beyond accepted body. |
| 对白/旁白 | `dialogue_or_narration` | Almost no | Only story-supported speech, narration, or safe fallback such as action-led emotion. | Do not let KB invent lines, slogans, source examples, or commentary. |
| 分镜提示词 | `prompt_text` | Yes, by compilation only | Current-row packaging of subject, frame, action, camera, shot size, dialogue/narration, duration, rhythm, style, constraints. | Do not paste raw KB, source URL, sample id, rule id, hash, local path, OCR, image filename, matrix id, or prompt library example. |
| 时长(秒) | `duration_seconds` | Limited | Duration suitability may guide pacing density only. | Do not let KB override the existing duration allocation total. |
| 操作 | UI action state | No | None. | Do not bind knowledge rules to UI actions. |

## Shot-Size-Aware Expression Boundary

| 景别 / `shot_size` | Allowed `character_action` detail | Blocked detail |
| --- | --- | --- |
| 特写 / 近景 | eyelid tension, gaze lock, lip pressure, jaw tension, nasal flare, trembling breath, tear line, cheek shift | Only broad body blocking with no visible expression. |
| 中近景 / 中景 | gaze direction, breath pause, shoulder contraction, hand hesitation, posture shift, small recoil | Pore-level, invisible, or over-specific facial muscle detail. |
| 全景 / 远景 / 航拍 | silhouette, stance, spacing, group movement, pause, retreat, advance, prop handling | Tiny eye, lip, cheek, jaw, or tear details. |
| 插入 / 细节 | hand, object, footprint, weapon, cloth, surface pressure, reflected eye, small visible clue | Whole-body emotional summary unless visible through the insert. |

## Adapter Admission Requirements

A knowledge item can enter runtime only if all bindings are present:

```text
reviewed_wiki_id
mapping_id
runtime_rule_pack_id
runtime_targets
pwa_snapshot_paths
pwa_storyboard_fields
consumed_by_actions
positive_directive
negative_constraint
review_status=reviewed
leakage_count=0
```

Allowed `pwa_storyboard_fields` are limited to:

```text
camera
shot_size
visual_description
character_action
dialogue_or_narration
prompt_text
note
```

If a knowledge item cannot map to one of these fields, it stays as background research and must not enter `runtime-kb-snapshot` or PWA output.

## Fast Safety Gate

Normal knowledge batches should pass this fast gate:

| gate | pass condition |
| --- | --- |
| Field fit | Every rule maps to an existing storyboard field. |
| No schema drift | No new PWA column, type, generation stage, provider path, or export shape is required. |
| No leakage | No raw KB, source URL, source text, local path, OCR, sample id, rule id, hash, or matrix id appears in output. |
| Shot consistency | `camera`, `shot_size`, `visual_description`, and `character_action` do not contradict each other. |
| Prompt compile | `prompt_text` is compiled from confirmed row fields, not copied from source examples. |
| Export safety | Excel export keeps the current agreed format and remains free of KB internals. |

Heavy gates such as `full16` and `403case` are reserved for provider, fallback, release, architecture, or live-403 risk. They are not the normal requirement for turning a reviewed KB knowledge batch into PWA-consumable guidance.
