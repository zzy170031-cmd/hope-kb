# PWA Adapter Contract v0.2

Status: adapter boundary baseline.
Scope: compile Hope-KB runtime snapshots into `hope-web-pwa` compatible
`KbSnapshot` and `SanitizedKbSummary` inputs.

## Purpose

The adapter is the explicit boundary between Hope-KB and `hope-web-pwa`.
Hope-KB owns reviewed wiki, graph governance, mapping, runtime snapshot, and
coverage validation. The PWA owns content production. The adapter must not make
KB the product center; it only transforms approved KB support content into the
shape the PWA can safely consume.

## Input

Adapter input is a verified KB-side candidate or activated artifact:

```text
knowledge/runtime_snapshots/latest.candidate.json
knowledge/mappings/wiki-to-runtime-mapping.v0.2.json
docs/product-action-crosswalk-v0.2.md
```

For Batch 1, the input is prototype-scoped and covers only the narrow scene set
declared in the snapshot. It must not be represented as full PWA catalog
coverage.

## Output

Adapter output is a wrapped artifact:

```text
{
  "adapter_version": "pwa-kb-adapter/v0.2",
  "adapter_status": "prototype",
  "source_snapshot_version": "...",
  "source_snapshot_hash": "...",
  "scene_catalog_status": "partial",
  "rule_pack_crosswalk_status": "prototype",
  "pwa_snapshot": { "...": "PWA KbSnapshot-shaped data" },
  "sanitized_summary_contract": { "...": "summary-only field contract" },
  "fail_closed": { "...": "fallback conditions" }
}
```

The Batch 1 prototype sample is generated by:

```text
node scripts/build-pwa-kb-adapter-output.js
node scripts/build-pwa-kb-adapter-output.js --check
```

The `--check` mode must pass before treating the sample as current.

`pwa_snapshot` must use the field names expected by `hope-web-pwa`:

```text
snapshotVersion
sceneTypes
allowedDurations
writingRulePacks
directorRulePacks
validationRulePacks
sceneMappings
durationProfiles
```

Rule packs must use PWA `RulePack` shape:

```text
id
name
intent
influenceAxes
directives
negativeConstraints
```

Scene mappings must use PWA `sceneMappings` shape:

```text
writingRulePackIds
directorRulePackIds
validationRulePackIds
sceneProfile
negativeConstraints
influenceAxes
```

Duration profiles must use PWA `DurationCapacityProfile` shape:

```text
duration
targetShotCount
beatDensity
pacingDirective
```

## Crosswalk Rule

Batch 1 KB rule pack ids may differ from the current `hope-web-pwa` in-code
rule ids. The adapter must either:

- preserve KB ids and require the PWA loader to accept external ids; or
- map KB ids to current PWA ids through a documented crosswalk.

The Batch 1 prototype output uses a documented crosswalk status, not a claim
that product rule-id migration is complete.

## Runtime Activation Boundary

The current `hope-web-pwa` consumer can load the wrapped adapter artifact at
`/kb/latest.json`, but Batch 1 remains a prototype activation. A product run may
use this artifact only when the PWA loader explicitly opts in to both:

```text
allowPrototype=true
allowPartialSceneCatalog=true
```

This opt-in is not a permanent product default. It is allowed only for the
current PWA runtime-consumption gate and only because the artifact still reports:

```text
adapter_status=prototype
scene_catalog_status=partial
rule_pack_crosswalk_status=prototype
```

The next activation level must either promote the adapter to verified/full
coverage, or keep the same explicit opt-in and label the run as prototype. A
partial catalog must never be silently treated as complete product coverage.

As of the first PWA runtime consumer anchor:

```text
hope-web-pwa main ee350c7 feat: load runtime KB adapter snapshot
```

the PWA runtime consumes the adapter snapshot for `SanitizedKbSummary`,
duration options, duration profiles, and prompt rule directives. This does not
add PWA fields, add generation stages, or change export shape.

## Fail-Closed Rule

The PWA loader must reject and fall back to a built-in safe default when any of
these are true:

- adapter output is absent or unparsable;
- `adapter_status` is not accepted by the loader;
- `pwa_snapshot` misses required camelCase fields;
- scene catalog status is `partial` but the product path requires full catalog;
- rule pack ids referenced by `sceneMappings` do not exist in rule pack arrays;
- durations are missing or not positive integers;
- any raw KB, raw graph, source register, prompt body, local path, provider
  config, key, token, secret, or internal governance evidence is present.

Current effective fallback target:

```text
hope-web-pwa built-in KB_SNAPSHOT
```

`last-known-good adapter output` is a reserved future consumer behavior. It is
not active in the current PWA runtime gate and must not be claimed as verified
until the PWA implements local persistence, freshness checks, and tests for that
fallback path.

If the wrapped artifact still contains a broader textual `fallback_target`, the
consumer contract must interpret it through this section: current verified
behavior is built-in fallback only.

## Artifact Freshness And Handoff Rule

The runtime handoff is current only when all of these match the same KB-side
snapshot generation:

```text
samples/pwa-kb-adapter-output.sample.json
hope-web-pwa/public/kb/latest.json
hope-web-pwa/dist/kb/latest.json
```

Required freshness evidence:

```text
node scripts/build-pwa-kb-adapter-output.js --check
node scripts/sync-pwa-kb-latest.js --pwa-root <hope-web-pwa-root>
PWA loader/type tests
PWA build
```

The PWA loader should fetch `/kb/latest.json` without using a stale browser
cache. A stale adapter artifact must be treated like any other failed adapter
load unless freshness has been explicitly re-established by the handoff checks.

## Summary-Only Rule

The PWA may produce only `SanitizedKbSummary` style data from adapter output.
It may expose rule-pack ids and selected rule ids internally for control flow,
but user-facing prompts, UI, traces, and exports must stay summary-only.

The allowed downstream summary surface remains:

```text
kb_snapshot_hash
scene_type_count
scene_type_id
scene_type_label
duration_options
selected_sample_ids
selected_kb_rules
writing_group_rule_pack_ids
director_group_rule_pack_ids
kb_context_summary
applied_to
action_results
influence_axes
scene_profile
negative_constraints
kb_oracle_affects_structure
raw_kb_rows_included=0
raw_sample_text_absent=true
source_register_absent=true
overlay_json_absent=true
prompt_body_absent=true
```

No raw KB rows, raw source text, source register, overlay JSON, prompt body,
provider config, local path, key, token, secret, or internal governance evidence
may enter prompt text, visible UI, QA trace intended for users, or export
artifacts.

## QA Observability Boundary

The PWA may expose compact non-secret adapter state for QA and support:

```text
kb_adapter_source
kb_adapter_reject_reason
kb_snapshot_hash
scene_catalog_status
adapter_status
```

These are QA/support fields only. They must not expose raw KB rows, raw source
text, prompt bodies, source registers, local paths, provider configuration, or
credential values. Adding these QA fields does not open a new PWA product
contract or a new storyboard output field.

## Required Release Evidence

Batch 1 prototype closure requires only structure validation. Product
integration requires stronger evidence:

- JSON Schema validation for adapter output;
- PWA loader/type tests;
- fail-closed tests for absent, invalid, stale, partial, and unsafe adapter
  artifacts;
- raw leakage tests across prompts, UI traces, and exports;
- real hash recomputation replacing `sample-*` placeholders;
- full scene catalog decision: either full PWA catalog coverage or explicit
  product gating for partial catalog use.
## Visual Reference Matrix Consumption Rule

Visual reference evidence matrices are KB-side evidence artifacts. They are not
PWA runtime artifacts. A visual reference rule may enter the PWA consumption path
only when it has a reviewed projection into the existing adapter output shape.

Required projection for every runtime-eligible visual matrix row:

```text
matrix_entry.reviewed_wiki_id
matrix_entry.runtime_projection.mapping_id
matrix_entry.runtime_projection.runtime_rule_pack_id
matrix_entry.runtime_projection.runtime_targets
matrix_entry.runtime_projection.pwa_snapshot_paths
matrix_entry.runtime_projection.pwa_storyboard_fields
matrix_entry.runtime_projection.consumed_by_actions
```

Allowed PWA snapshot paths are limited to the existing adapter surface:

```text
pwa_snapshot.writingRulePacks[].directives
pwa_snapshot.writingRulePacks[].negativeConstraints
pwa_snapshot.directorRulePacks[].directives
pwa_snapshot.directorRulePacks[].negativeConstraints
pwa_snapshot.validationRulePacks[].directives
pwa_snapshot.validationRulePacks[].negativeConstraints
pwa_snapshot.sceneMappings.*.writingRulePackIds
pwa_snapshot.sceneMappings.*.directorRulePackIds
pwa_snapshot.sceneMappings.*.validationRulePackIds
pwa_snapshot.sceneMappings.*.sceneProfile
pwa_snapshot.sceneMappings.*.negativeConstraints
pwa_snapshot.sceneMappings.*.influenceAxes
pwa_snapshot.durationProfiles[].pacingDirective
```

Allowed PWA storyboard fields are limited to the current product fields:

```text
camera
shot_size
visual_description
character_action
dialogue_or_narration
prompt_text
note
```

If a visual matrix row cannot map to both a PWA snapshot path and a PWA
storyboard field, it may remain raw evidence or reviewed KB background, but it
must not be emitted by the adapter as runtime guidance.

The adapter must not emit visual matrix ids, duplicate group ids, image file
names, local paths, OCR text, screenshot text, tutorial source text, or raw
source notes. It may emit only rewritten summary directives and negative
constraints through the PWA snapshot fields above.

This keeps the chain coupled without copying source material into production:

```text
visual-reference-evidence-matrix -> reviewed wiki -> wiki-to-runtime mapping
-> runtime-kb-snapshot -> build-pwa-kb-adapter-output -> pwa_snapshot
-> PWA prompt generation and export
```
## Product Architecture Stability Rule

Knowledge expansion must not change the PWA architecture. The adapter may enrich
existing rule packs, scene mappings, influence axes, negative constraints, and
summary fragments, but it must not require new PWA stages, new storyboard row
fields, or alternate generation flows.

All KB additions for camera movement, micro-expression, scene description,
Seedance-oriented prompt vocabulary, or visual reference guidance must be
projected into existing PWA surfaces:

```text
writingRulePacks
directorRulePacks
validationRulePacks
sceneMappings
durationProfiles
SanitizedKbSummary
```

And into existing storyboard output fields:

```text
camera
shot_size
visual_description
character_action
dialogue_or_narration
prompt_text
note
```

The PWA remains the product runtime. KB remains a reviewed support layer. If a
candidate knowledge item cannot be consumed through the existing adapter shape
and existing storyboard fields, it must stay in KB review/future work and must
not be emitted as runtime guidance.
